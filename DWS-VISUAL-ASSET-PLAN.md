## Current original treatments
- Hero: precise existing vector in a restrained lit interface surface, with a short module reveal; it is not represented as a finished 3D render.
- Build system: interactive IDEA / BUILD / GROW study using a crop of the original vector, without changing its paths or relationships.
- Builder: actual production interface and a linked homepage preview; no invented client screenshots.
- Blueprint: actual approved cover plus labelled format previews for architecture and 30/60/90 planning. No invented client/company fields.
- Systems: accessible Lead / Content pathways and a user-triggered connection trace; approval remains explicit and execution disabled.
- In-house proof: Brand, Digital and Automation exploration uses the studio's own identity and product interfaces. It is clearly separated from client work.

## Media insertion contracts
ApprovedExperienceMedia in data/digital-experience.ts supports approvalReference, desktop poster, optional mobile poster and optional user-controlled video. heroExperienceMedia stays null until approved. Raster sources should be AVIF/WebP with real dimensions, responsive sources and reviewed alt text. No blank image requests are emitted while absent.

Project publication continues through lib/content.ts. A project must have published status and an explicit publicationApproval reference covering copy, media, rights and exact revision. Full-frame portfolio chapters consume only those records. Optional exhibition background/foreground are six-digit hex colors with a separate approval reference; check contrast before acceptance. Artwork is never recolored. No actual client palette is guessed in this release.

Case modules already support desktop/mobile devices, controlled films with poster frames, comparison, packaging, lineup, details, dieline, environment, retail, technical and mobile sequences. Prepare dedicated desktop/mobile crops and legible screen captures rather than generic laptop imagery. Client animation must have a static fallback and accessible controls.

## Performance acceptance for future assets
Do not load every asset family on the homepage. Hero poster is the sole priority image; reserve dimensions and lazy-load lower content. Target <=650 KB total initial compressed homepage transfer before optional media; <=240 KB desktop hero and <=110 KB mobile hero. Video is user-initiated, preload none, with a poster; do not add WebGL/3D libraries until an approved model and measured benefit justify them. Cap model/texture budgets separately if a real 3D implementation is approved. Review on a high-density device, low-end mobile and throttled network before activating large assets.
